# Native network and app proxy architecture

The implementation is intentionally small: runc/CRIU, existing Linux namespaces,
veth, nftables and the existing worker operation/helper ownership model. No VM
storage, network daemon, outbound HTTP relay, domain-policy engine or S3 client.

## Authority and topology

```text
controller: authenticated requests, routed by sandbox ID (app proxy: path form or
    |       <port>-<sandbox-id>.<proxy_domain> hosts, streamed to the owner)
    |
worker admission: durable record + exclusive pool slot + per-sandbox exclusion
    |
    +-- guest netns (per sandbox)           pooled router-slot netns (pre-created)
    |   192.0.2.2/30 eth0 -- veth inside -- 192.0.2.1/30      (attached at create)
    |   runc workload                       nft default drop; template's TCP permits
    |   UID/GID 65534, no capabilities       private SNAT to the slot's pool address
    |   seccomp: io_uring/MPTCP guards only     |
    |                                         uplink -- veth -- operator bridge
    |                                                          stable MAC/gateway
    +-- app proxy: a fresh TCP connection opened inside the router slot only
        (short-lived thread setns) -> 192.0.2.2:<approved service port>
```

Every guest has the same address, isolated by its own guest **and router** netns.
Router slots are pooled, following the AgentENV network manager (`allocate_slot`,
`release`): each slot index owns one pool address and, once built, keeps its
namespace, uplink veth on the bridge, address, routes and default-deny nftables
base (filter chains with drop policy and no rules, plus the SNAT rule) between
sandboxes. A slot holds at most one sandbox at a time.
The unique pool address is outside the guest: independent restores do not need to
rewrite an address embedded in a listening socket. The operator configures a
bridge/gateway/prefix, an exclusive pool, exact IPv4 destination/port ceiling and
service-port ceiling. The bridge must have an explicitly assigned stable MAC;
auto-selection from changing veth ports is unsuitable. Preflight checks bridge
kind/address/prefix and serialized bounds, not end-to-end routing or remote service
readiness. External routing and avoiding pool overlap with other workers/peers are
operator responsibilities. The worker never repairs global routing/firewall/sysctls.

Manifest v3 contains the policy. `isolated` creates no external links: the worker
still creates and owns the sandbox's guest netns (same ownership marker, names,
cleanup and restart reconciliation as networked sandboxes), but brings up only
loopback in it, adds no veth, address or route, attaches it to no router slot, and
disables IPv6. (On a network-enabled worker its reserved pool slot stays unused and
clean.) This remains the default configuration. The worker creates the namespace itself
because runc checkpoints always treat the network namespace as empty: a namespace
runc created would restore with loopback down, breaking restored loopback
connections, while a worker-created one passed by path keeps it. `tcp_allowlist`
permits only its operator-approved subset. No create-time endpoint override exists
in this milestone: changing a tool endpoint requires a different immutable template.
Policies are not a universal reusable-template destination abstraction.

The router namespace enforces IPv4 source/destination/port and direction, with
established-only replies. IPv4 fragmentation-needed errors may return to the guest
only when conntrack classifies them as related to an existing authorized TCP flow,
matching the original guest source and approved destination/port. This includes
errors forwarded from downstream routers and errors generated by the slot itself;
it is not a general ICMP or RELATED accept rule. TCP path-MTU discovery therefore
works without opening workload ICMP/raw sockets or relying on black-hole probing.
All other forwarding/input/output is dropped. Only its
own approved service-port TCP requests can leave the router toward the guest;
untrusted workload replies to those requests require established state. Unsolicited
uplink ingress cannot reach guest services. IPv6 is disabled in both owned
namespaces. There is no implicit DNS. Seccomp no longer filters socket families: it
follows the AgentENV pattern (default-allow; io_uring returns ENOSYS and MPTCP sockets
EPROTONOSUPPORT, for CRIU checkpointability only). Workloads may create UDP, IPv6
or Unix sockets, but only the router nftables rules decide what leaves the guest.
Empty workload capabilities still prevent raw/packet sockets, namespace changes
and mounts; no_new_privs and cgroups remain in force.

## Ownership and ordering

1. Worker start (after restart reconciliation) builds the pool: one slot for each
   sandbox the worker can admit (`max_sandboxes`, bounded by the address pool).
   Each slot first durably creates its ownership directory `slots/<index>` under
   the worker root, then, through trusted bounded helpers, its namespace pin
   (IPv6 disabled, IPv4 forwarding on), the uplink veth with its pool address, the
   default-deny nftables base loaded atomically, and only then attaches the host
   end to the existing bridge, brings the links up and adds the default route. A
   slot that fails to build is removed and built lazily by the next create that
   is assigned its index.
2. Admission atomically reserves capacity, operation slot and the lowest free
   network-pool index in the durable sandbox record. Guest names incorporate root
   and sandbox digests; slot names incorporate the root digest and the index.
3. Before resource creation, verify the guest name is absent and durably create an
   exclusive private ownership marker. Do not adopt unexplained existing namespaces.
4. Create the guest namespace pin (loopback up, IPv6 disabled); isolated sandboxes
   stop here. Otherwise claim the slot (a missing or unknown one is rebuilt now),
   atomically replace its rules with the template's (`flush table` plus the exact
   permits in one nftables transaction), then create the `inside`/`eth0` veth pair
   into the guest, its addresses and the guest default route.
5. Bring the guest links up only after the rules succeed, then run/restore runc. The
   guest OCI network namespace points to its worker-owned pin. Warm OCI
   normalization replaces only reconstruction paths; the network-policy digest
   stays bound.
6. Delete/cancel waits for its in-flight job, drains tracked helper descendants,
   kills workload cgroups and removes runc state. It then returns the slot to the
   pool: delete the slot's `inside` end (which removes the guest's `eth0` at once,
   even if something still holds the guest namespace), flush the template rules
   back to the default-deny base and flush the slot's connection tracking (a
   netlink request from a same-binary helper inside the slot, after it checks that
   no guest link remains), so the next sandbox inherits no rules, flows or NAT
   mappings. A slot that cannot be reset is deleted instead (its host link removal
   is awaited) and rebuilt later. Finally the guest pin is dropped. Failures retain
   the marker, files and reservation for retry; no broad flush or unrelated
   interface cleanup occurs.
7. Restart drains root-specific helper cgroups before any namespace/private/staging
   cleanup. Records, slot ownership directories and root-specific namespace names
   are checked for unexplained ownership; old live workloads are terminated, never
   silently adopted. Pooled slots are not adopted either: after the sandboxes are
   cleaned up every owned slot is deleted and the pool is built fresh (step 1).
   Shutdown, once every sandbox is gone, deletes the whole pool.

The worker's short coordinator and bounded I/O pool are unchanged. Different
sandboxes overlap; one sandbox's create/capture/delete do not race, and capture
waits for no command (it is refused while one runs). Caller cancellation does not
orphan an accepted job or command. Each mutating host process and its descendants
joins an exclusive restart-discoverable helper cgroup before exec. Proxied app
traffic needs no host process: the worker itself holds the connection.

## Capture and established connections

Capture follows AgentENV: CRIU dumps and restores established TCP connections
(`--tcp-established`), with `network-lock nftables` while the source is checkpointed
and while a child restores, and the source keeps running (`--leave-running`). There
is no TCP-state precheck. Connections not yet accepted by a frozen application are
skipped (`skip-in-flight`); the source serves them after the thaw. Because every
guest has the same address in its own worker-created namespace, a captured socket's
local address exists in every child, so listening sockets and loopback connections
inside the sandbox restore and keep working (gate-tested). A connection to an external
peer is restored only on the child's side: no external peer, router conntrack/NAT
state or SNAT address is checkpointed, and the child gets a different router slot
(reset, with empty connection tracking) and its own pool address, so the child's
copy fails on first use while the source keeps the original. Fresh post-restore outbound connections work normally. A
successful fixture is not broad application or cross-host checkpoint qualification.

Manifest v1/v2 and older layout fingerprints are deliberately incompatible.
The new schema/layout also applies to newly provisioned isolated templates; there
is no silent interpretation of old deny-all artifacts as network-enabled images.

## App proxy boundary

App traffic follows AgentENV's gateway and node proxy (`services/gateway`
`host_route.go`/`server.go`, `src/api/proxy.rs`). The controller accepts a request
whose Host is `<port>-<sandbox-id>.<proxy_domain>` (configured `proxy_domain`; the
sandbox ID is used verbatim, so the host has one more label than AgentENV's) or the
path form `/v1/sandboxes/<id>/proxy/<port>/<path>`. It requires the management bearer
token, routes by the ID's owner prefix to a fresh owner and streams the exchange to
the worker with the worker token. The worker accepts only a running (or capturing)
sandbox and a port in its template's approved `service_ports` (which the operator
ceiling already bounds), then opens a **new TCP connection from inside the sandbox's
router slot**: a short-lived thread enters the pinned slot namespace with `setns`,
creates the socket and exits, so no shared worker or Tokio thread ever changes
namespace and nothing listens on or routes from the host network. The slot's
existing nftables rules allow exactly the slot-to-guest service-port flow
(`output oifname inside ... tcp dport <port>` and established replies). One request
per connection; nothing is pooled across exchanges (guest addresses are reused).

The request and response are forwarded as HTTP/1.1 messages, not reinterpreted:
the method, raw path and query, headers and status are the application's; bodies
stream in both directions with their framing (Content-Length kept, chunked
re-chunked as it arrives), so large, binary and long-lived bodies work. Hop-by-hop
headers (and those Connection names), `Proxy-Authorization` and the management
`Authorization` header are removed; Host becomes `192.0.2.2:<port>`, with
`X-Forwarded-Host` (the client's original host) and `X-Forwarded-Proto` set by the
controller, which drops client-supplied `X-Forwarded-*`/`Forwarded`. A request that
asks to upgrade (WebSocket) keeps its Upgrade headers, and a 101 answer turns both
hops into byte tunnels. Redirects are returned, not followed.

Bounds: `[server.proxy] max_connections` open exchanges per service (default 256;
503 `busy` beyond it) and `idle_timeout_ms` (default 600,000, AgentENV's response-head
wait): the sending side must move a byte within that period — the response head,
the next frame of either body, a tunnel's reads and blocked writes (504
`upstream_timeout` from the worker, `owner_response_timeout` from the controller). A
receiver that stops reading is not timed out; its exchange holds its permit until it
reads or disconnects. There is no total deadline: the client decides. A guest that
refuses or drops the connection is 502 `upstream_unavailable`. Deleting the sandbox,
its TTL expiry or the end of its running state ends its open exchanges, including
ones still connecting or waiting for the response head (502), so a reset slot never
hands a pending exchange to its next sandbox; a stalled body sees the close at its
next read.
See the [API](api.md#app-proxy) and the
[disposable qualification recipe](runtime.md#disposable-network-qualification).

Remaining work: per-create bounded policy selection, broader workload compatibility,
hardened-host/network deployment qualification, cross-node restore, disk quotas,
S3 transport and agreed capacity/latency qualification. None is implied by this
local implementation or its targeted fixture results.
