# Native network and application HTTP architecture

The implementation is intentionally small: runc/CRIU, existing Linux namespaces,
veth, nftables and the existing worker operation/helper ownership model. No VM
storage, network daemon, outbound HTTP relay, domain-policy engine or S3 client.

## Authority and topology

```text
controller: authenticated blocking requests, routed by sandbox ID
    |
worker admission: durable record + exclusive pool slot + per-sandbox exclusion
    |
    +-- guest netns                         private router-slot netns
    |   192.0.2.2/30 eth0 -- veth inside -- 192.0.2.1/30
    |   runc workload                       nft default drop; exact TCP permits
    |   UID/GID 65534, no capabilities       private SNAT to unique pool address
    |   seccomp: io_uring/MPTCP guards only     |
    |                                         uplink -- veth -- operator bridge
    |                                                          stable MAC/gateway
    +-- bounded HTTP helper enters router slot only
        reqwest -> http://192.0.2.2:<approved service port>/<validated path>
```

Every guest has the same address, isolated by its own guest **and router** netns.
The unique pool address is outside the guest: independent restores do not need to
rewrite an address embedded in a listening socket. The operator configures a
bridge/gateway/prefix, an exclusive pool, exact IPv4 destination/port ceiling and
service-port ceiling. The bridge must have an explicitly assigned stable MAC;
auto-selection from changing veth ports is unsuitable. Preflight checks bridge
kind/address/prefix and serialized bounds, not end-to-end routing or remote service
readiness. External routing and avoiding pool overlap with other workers/peers are
operator responsibilities. The worker never repairs global routing/firewall/sysctls.

Manifest v2 contains the policy. `isolated` creates no external links (the guest
netns has only loopback); this remains the default configuration. `tcp_allowlist`
permits only its operator-approved subset. No create-time endpoint override exists
in this milestone: changing a tool endpoint requires a different immutable template.
Policies are not a universal reusable-template destination abstraction.

The router namespace enforces IPv4 source/destination/port and direction, with
established-only replies. IPv4 fragmentation-needed errors may return to the guest
only when conntrack classifies them as related to an existing authorized TCP flow,
matching the original guest source and approved destination/port. This includes
errors forwarded from downstream routers and errors generated by the slot itself;
it is not a general ICMP or RELATED accept rule. TCP path-MTU discovery therefore
works without opening workload ICMP/raw sockets or relying on black-hole probing.
All other forwarding/input/output is dropped. Only its
own approved service-port TCP requests can leave the router toward the guest;
untrusted workload replies to those requests require established state. Unsolicited
uplink ingress cannot reach guest services. IPv6 is disabled in both owned
namespaces. There is no implicit DNS. Seccomp no longer filters socket families: it
follows the AgentENV pattern (default-allow; io_uring returns ENOSYS and MPTCP sockets
EPROTONOSUPPORT, for CRIU checkpointability only). Workloads may create UDP, IPv6
or Unix sockets, but only the router nftables rules decide what leaves the guest.
Empty workload capabilities still prevent raw/packet sockets, namespace changes
and mounts; no_new_privs and cgroups remain in force.

## Ownership and ordering

1. Admission atomically reserves capacity, operation slot and network-pool index in
   the durable sandbox record. Names incorporate root and sandbox digests.
2. Before resource creation, verify names are absent and durably create an exclusive
   private ownership marker. Do not adopt unexplained existing namespaces/links.
3. Create guest/router namespace pins and down veths through trusted bounded helpers.
   Disable IPv6 only inside these namespaces. Install router nftables atomically;
   configure addresses/routes and attach the unique uplink to the existing bridge.
4. Bring links up only after the filter succeeds, then run/restore runc. The guest
   OCI network namespace points to its worker-owned pin. Warm OCI normalization
   replaces only reconstruction paths; the network-policy digest stays bound.
5. Delete/cancel waits for its in-flight job, drains tracked helper descendants,
   kills workload cgroups, removes runc state, then drops namespace pins. Kernel
   link destruction is awaited. Failures retain the marker, files and reservation
   for retry; no broad flush or unrelated interface cleanup occurs.
6. Restart drains root-specific helper cgroups before any namespace/private/staging
   cleanup. Records and root-specific namespace names are checked for unexplained
   ownership; old live workloads are terminated, never silently adopted.

The worker's short coordinator and bounded I/O pool are unchanged. Different
sandboxes overlap; one sandbox's exec/capture/HTTP/delete do not race. HTTP caller
cancellation does not orphan an accepted task. Each mutating host process and its
descendants joins an exclusive restart-discoverable helper cgroup before exec.

## Capture is not external connection cloning

Application listening sockets and **fresh** post-restore outbound connections are
the contract. Close accepted/outbound TCP connections before capture. A bounded
namespace TCP-state precheck rejects active/closing sockets before stopping; CRIU
still rejects unsupported state/races, without TCP-established or external-socket
waivers. Failed/uncertain dumps retain the existing conservative source-termination
behavior. No external peer or router conntrack/NAT state is checkpointed. A restored
child gets a newly constructed router and its own pool address, not the source's
remote connection identity. A successful listening-socket fixture is not broad
application or cross-host checkpoint qualification.

Manifest v1 and the old isolated layout fingerprint are deliberately incompatible.
The new schema/layout also applies to newly provisioned isolated templates; there
is no silent interpretation of old deny-all artifacts as network-enabled images.

## Application HTTP boundary

`POST /v1/sandboxes/{id}/http` is a blocking bounded request, not a URL proxy. The
worker validates fixed-target service authorization and launches its own executable
via the verified `ip` into **only the selected router namespace**. Namespace entry
never touches a pooled worker/Tokio thread. The request is a protected private JSON
file, not command-line secrets; the helper inherits no management environment.

The maintained reqwest client has no proxy or redirects, one HTTP/1 request,
bounded deadline/body/result, and no connection pooling across operations. Inputs
are a small method set, relative path/query, optional accept/content-type and UTF-8
text. Management bearer, Host and arbitrary headers are not forwarded. Results
contain status, content-type and UTF-8 body only and are returned inline, never stored. Invalid UTF-8 is rejected, not
silently corrupted. Whole helper-cgroup drainage bounds descendants, output and
restart lifetime. Application failures do not kill an otherwise healthy sandbox.
See [API bounds](api.md#application-http) and the
[disposable qualification recipe](runtime.md#disposable-network-qualification).

Remaining work: per-create bounded policy selection, broader workload compatibility,
hardened-host/network deployment qualification, cross-node restore, disk quotas,
S3 transport and agreed capacity/latency qualification. None is implied by this
local implementation or its targeted fixture results.
